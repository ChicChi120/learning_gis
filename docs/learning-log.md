## 2026-10-29 Phase 1: データ取得と読込・CRS 確認
- やったこと: N03(愛知県・2026-01-01 基準)と OSM 変電所(Overpass Turbo)を取得して data/raw/ に配置、出典・ライセンスを docs/data_sources.md に記録、QGIS で 3 レイヤ(N03 .shp、変電所の点・面)を読み込み CRS を確認
- 分かったこと: N03 は CC BY 4.0、OSM は ODbL でクレジット表記が異なる / OSM は取得日時(timestamp_osm_base)が版になる / OSM は node・way・relation で構成され、変電所は点と面が混在する(Polygon 230・Point 18)/ N03 は EPSG:6668(JGD2011)、OSM GeoJSON は EPSG:4326(WGS 84)で、どちらも単位が度の地理座標系
- つまずき/未解決: ODbL のシェアアライクが成果物(GPKG と地図画像)にどう関係するか / N03 が 1,033 件ある理由 / .shp は Polygon、.geojson は MultiPolygon と表示される理由
- 次回: QGIS のプロジェクト CRS とオンザフライ再投影を確認し、計測ツールで距離を測って単位と計算方法を確かめる

## 2026-11-02 Phase 1: プロジェクト CRS・計測ツール・再投影
- やったこと: プロジェクト CRS を EPSG:6668 と EPSG:6675 で切り替え、スナップで固定した 2 点を Cartesian / Ellipsoidal で計測 / 「ベクタレイヤを再投影」で変電所の点を EPSG:6675 にして data/processed/substation_points_6675.gpkg に保存(18 件)/ N03 の属性テーブルで同じコードが複数行ある市町村を確認
- 分かったこと: プロジェクト CRS を変えても表示が変わるだけで、レイヤ CRS は変わらない(オンザフライ再投影)/ Ellipsoidal の距離はプロジェクト CRS に左右されない(両方 64485.181 m)/ EPSG:6668 の Cartesian は度(0.655 度)で、同じ度でも方角によって距離が変わるため、1 つの係数でメートルに換算できない(真南北なら約 72.7 km、真東西なら約 59.6 km)/ EPSG:6675 の Cartesian は 64478.888 m で、比 0.99990241 は平面直角座標系の X 軸上の縮尺係数 0.9999 に近い / バッファの単位は入力レイヤの CRS で決まるため、プロジェクト CRS ではなく入力レイヤを EPSG:6675 に再投影する / 「レイヤの CRS を設定」は変換ではなくラベルの貼り替え / N03 は 1 行=1 市町村ではないため、市区町村ごとにまとめて集計する必要がある
- つまずき/未解決: 行をまたぐ比較で別の 2 点を測り、Ellipsoidal の値が約 2,800 m ずれた(スナップで解決)/ cos(35°) を km と取り違えた / 6675 にする対象をプロジェクト CRS と混同した / 小さな行・棒状の図形の正体、集計キー(N03_004 か N03_007 か)、所属未定地の扱いは未回答 / .shp が Polygon、.geojson が MultiPolygon と表示される理由 / ODbL のシェアアライクが成果物にどう関係するか
- 次回: N03 の小さな図形の正体を確かめ、集計キーと所属未定地の扱いを決める
