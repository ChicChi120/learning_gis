## 2026-11-02 Phase 1: プロジェクト CRS・計測ツール・再投影
- やったこと: プロジェクト CRS を EPSG:6668 と EPSG:6675 で切り替え、スナップで固定した 2 点を Cartesian / Ellipsoidal で計測 / 「ベクタレイヤを再投影」で変電所の点を EPSG:6675 にして data/processed/substation_points_6675.gpkg に保存(18 件)/ N03 の属性テーブルで同じコードが複数行ある市町村を確認
- 分かったこと: プロジェクト CRS を変えても表示が変わるだけで、レイヤ CRS は変わらない(オンザフライ再投影)/ Ellipsoidal の距離はプロジェクト CRS に左右されない(両方 64485.181 m)/ EPSG:6668 の Cartesian は度(0.655 度)で、同じ度でも方角によって距離が変わるため、1 つの係数でメートルに換算できない(真南北なら約 72.7 km、真東西なら約 59.6 km)/ EPSG:6675 の Cartesian は 64478.888 m で、比 0.99990241 は平面直角座標系の X 軸上の縮尺係数 0.9999 に近い / バッファの単位は入力レイヤの CRS で決まるため、プロジェクト CRS ではなく入力レイヤを EPSG:6675 に再投影する / 「レイヤの CRS を設定」は変換ではなくラベルの貼り替え / N03 は 1 行=1 市町村ではないため、市区町村ごとにまとめて集計する必要がある
- つまずき/未解決: 行をまたぐ比較で別の 2 点を測り、Ellipsoidal の値が約 2,800 m ずれた(スナップで解決)/ cos(35°) を km と取り違えた / 6675 にする対象をプロジェクト CRS と混同した / 小さな行・棒状の図形の正体、集計キー(N03_004 か N03_007 か)、所属未定地の扱いは未回答 / .shp が Polygon、.geojson が MultiPolygon と表示される理由 / ODbL のシェアアライクが成果物にどう関係するか
- 次回: N03 の小さな図形の正体を確かめ、集計キーと所属未定地の扱いを決める

## 2026-11-04 Phase 1: N03 の集計単位の決定と市区町村の融合
- やったこと: 「式による地物選択」で 1,000 ㎡ 未満の小さな図形の正体と、所属未定地(2 件)を確認 / 統計パネルで N03_004(55)と N03_007(70)のユニーク数を比較 / 「ベクタレイヤを再投影」(EPSG:6675)→「式による抽出」(`"N03_007" <> '23000'`)→「融合」(基準属性 N03_007)で data/processed/n03_municipalities_6675.gpkg を作成(69 件、面積合計 5.16909e+09 m² ≒ 5,169.09 km²)
- 分かったこと: 小さな図形は島で、1 行=1 つの閉じた図形のため 1 つの市が多数の行に分かれる(田原市は 642 行)/ 集計キーは N03_007(名古屋市を 16 区に分けたまま持てる。細かい単位から粗い単位へは後でまとめられるが逆は不可。名称よりコードの方が一意)/ 所属未定地は件数ではなく影響(面積約 3.08 km² = 全体の約 0.059%、変電所 0 件)を理由に除外し、3 フェーズすべてで同じ扱いにする / 融合は面積を変えず行のまとめ方だけを変える(5,172.17 − 3.08 = 5,169.09 km² で一致)/ `"..."` はフィールド名、`'...'` は文字列の値、`<>` は等しくない / `Polygon (MultiPolygon)` は大分類と格納形式の表示で、型の表示だけでは 1 行の面の数は分からない(Shapefile は単一と複数の面を区別せず、QGIS は MultiPolygon、GDAL は Polygon と表示する)/ `num_geometries($geometry) > 1` で複数の面を持つ行を数えられる(融合後 14 件、島の多い市と対応)
- つまずき/未解決: 「式による地物選択」と「式による抽出」の開き方が分からなかった / 融合前の N03 で `num_geometries($geometry) > 1` が何件になるかは未回答 / 複数の面を持つ 14 件がすべて島によるものか(飛び地の可能性)は未確認 / .shp と .geojson で表示が異なる件は「見るソフト・画面で表示が変わる」までで、.geojson 側は未確認 / ODbL のシェアアライクが成果物にどう関係するか
- 次回: 変電所を「1 か所 = 1 点」にするために、次の 4 項目を決める
  1. 面を点に変える方法: 面のどこを代表の点にするか
  2. 二重カウント: 同じ変電所が「点」と「面」の両方で登録されていないか
  3. 境界をまたぐ面: 1 つの変電所の面が 2 つの市区町村にまたがるときにどう数えるか
  4. 何を変電所とみなすか: OSM の鉄道用変電所なども含まれる。IoT の通信範囲というテーマに含めるか
  - 確認作業 A(考える問い、QGIS 操作なし): 「重心(Centroids)」と「地物上の点(Point on surface)」は、C 字や L 字の面でどう違うか。点で所属する市区町村を判定する目的には、どちらが安全か
  - 確認作業 B(二重カウント): 「位置による選択」で、選択するレイヤ = 変電所の点、空間的な条件 = 内側にある(within)、比較対象 = 変電所の面 として実行し、選ばれた点の件数と、地図上で同じ変電所に見えるかを確認する
  - 3 と 4 は A・B の結果を受けて扱う
